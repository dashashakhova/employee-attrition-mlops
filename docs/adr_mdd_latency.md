# ADR-001: Архитектурное решение по MDD для latency

## Status

Accepted

## Context

Для шага 5 задания предоставлены два синтетических набора latency по 500000 наблюдений. Средние значения заданы как 3.5 секунды для Existing System и 2.0 секунды для Improved System.

Это **данные из условия задания**, а не измерения Employee Attrition API.

## Decision

### H0

Среднее latency Improved System не меньше, чем у Existing System.

### H1

Среднее latency Improved System меньше, чем у Existing System.

### Statistical test

Используется Welch two-sample t-test для независимых выборок с `α = 0.05`.

Для предоставленных в задании выборок получено:

- t-statistic ≈ 1875.08;
- p-value = 0.0 в double precision, то есть фактически `p < 1e-300` и, в частности, `p < 0.001`.

Поскольку `p < α`, H0 отвергается.

### Architectural decision

Для синтетического эксперимента из задания выбирается Improved System: среднее latency уменьшается с 3.5 до 2.0 секунд, то есть примерно на 42.9%.

Это решение демонстрирует MDD: архитектурный выбор делается после статистической проверки метрики.

### Relation to this project

В реализованном Employee Attrition сервисе не проводилось сравнение двух готовых архитектур. Поэтому приведенный ADR является демонстрацией MDD по эксперименту из условия задания, а не отчетом о фактически проведенном сравнении двух архитектур проекта.

В собственном сервисе тот же принцип применяется к production-метрикам: P95 latency, error rate и model-quality metrics.
