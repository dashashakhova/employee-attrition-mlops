# ML-манифест проекта Employee Attrition Prediction Platform

## 1. Предыстория

Компания сталкивается с высокой текучестью персонала. Увольнение сотрудников приводит к прямым финансовым потерям, связанным с поиском, наймом и адаптацией новых работников. Руководству требуется инструмент для раннего выявления сотрудников с высоким риском увольнения.

## 2. Ценностное предложение

Система прогнозирует вероятность увольнения сотрудника и позволяет HR-специалистам своевременно предпринимать меры по удержанию ценных работников.

Преимущества системы:

* снижение текучести кадров;
* сокращение затрат на найм;
* повышение стабильности команд;
* автоматизация анализа кадровых рисков.

## 3. Цели

Основные задачи продукта:

1. Сбор и подготовка данных о сотрудниках.
2. Автоматическое обучение модели прогнозирования увольнения.
3. Оценка качества модели по заданным метрикам.
4. Автоматическая регистрация лучших моделей.
5. Предоставление API для получения прогнозов.
6. Мониторинг качества модели в продакшене.
7. Автоматический запуск переобучения при ухудшении качества.

Основная бизнес-метрика:

Снижение количества неожиданных увольнений сотрудников.

## 4. Решение

Система включает:

* пайплайн подготовки данных;
* обучение модели Logistic Regression;
* регистрацию моделей в MLflow;
* оркестрацию процессов через Apache Airflow;
* REST API на FastAPI;
* контейнеризацию через Docker;
* CI/CD через GitHub Actions;
* мониторинг работы модели.

В продукт не входят:

* автоматическое принятие кадровых решений;
* интеграция с корпоративными HRM-системами;
* хранение персональных данных сотрудников.

Заявленный уровень зрелости ML-системы: Level 2.

## 5. Осуществимость

Для реализации используются открытые технологии:

* Python;
* Scikit-Learn;
* FastAPI;
* MLflow;
* Airflow;
* Docker;
* GitHub Actions.

Все необходимые ресурсы доступны и не требуют приобретения коммерческих лицензий.

## 6. Данные

Источник обучающих данных:

IBM HR Analytics Employee Attrition Dataset.

Источник продакшн-данных:

Поток данных из HR-системы компании.

Разметка:

* Attrition = Yes → класс 1;
* Attrition = No → класс 0.

Удалены признаки:

* EmployeeCount;
* Over18;
* StandardHours;
* EmployeeNumber.

## 7. Метрики

Основная бизнес-метрика:

Снижение текучести персонала.

Технические показатели:

* доля выявленных сотрудников группы риска;
* количество успешных прогнозов увольнения.

## 8. Оценка качества модели

Офлайн-метрики:

* ROC-AUC;
* Precision;
* Recall;
* F1-score.

Результаты baseline-модели:

* ROC-AUC = 0.8034;
* Precision = 0.8095;
* Recall = 0.3617;
* F1-score = 0.5000.

Онлайн-метрики:

* latency API;
* количество запросов;
* распределение предсказаний;
* признаки data drift.

## 9. Подбор модели

Подход реализуется итеративно.

Итерация 1:

* Logistic Regression (baseline).

Следующие итерации:

* Random Forest;
* Gradient Boosting;
* XGBoost.

Новая модель переводится в Production только при улучшении ROC-AUC относительно текущей модели.

## 10. Инференс

Система использует режим реального времени.

Пользователь отправляет запрос через REST API.

FastAPI выполняет инференс и возвращает вероятность увольнения сотрудника.

## 11. Обратная связь

Источники обратной связи:

* фактические увольнения сотрудников;
* статистика использования API;
* мониторинг качества модели;
* признаки деградации данных.

Для принятия решений используется подход Metrics Driven Development (MDD).

Решения о переводе модели в Production принимаются на основании метрик качества.

## 12. Управление проектом

Конечные результаты:

* обучаемая модель;

* система управления экспериментами;
* оркестратор процессов;
* CI/CD-конвейер;
* мониторинг качества.
